# Motor de transición de billetera: candidato aislado

El pasivo por deuda se registra en wallet_transactions.debt_delta; saldo neto = real + promocional − deuda. El saldo comercial es una subcuenta del saldo real, no dinero adicional. La reserva puede incluir crédito, con una sola reserva abierta/consumida con deuda por conductor; una cancelación libera el derecho, una liquidación lo consume. La deuda no se paga con premios promocionales, sí mediante recargas confirmadas o ganancias comerciales reales. El cierre usa recargas/bonos recibidos durante el viaje antes de crear la deuda. Crédito nunca es un ingreso.

Ganancia comercial liberada solo cuando se liquida toda deuda del viaje y la comisión real cobrada (sin reutilizar ganancias ni bonos) cubre el premio; financiación pendiente permanece visible. Correcciones de recargas que respaldan recompensas ya pagadas se bloquean para reconciliación explícita; no se retira dinero ajeno a ganancias. Retirada >= mínimo y <= saldo comercial libre, con deuda cero, reserva, aprobación manual, referencia y auditoría. La aprobación registra el pago que el administrador ya realizó, no ejecuta transferencia. No se borra ledger.

El candidato no pone engine_ready=true ni activa cobro; requiere pruebas, verificación de todas las rutas, despliegue UI y revisión de informes. Activación conjunta protegida: 15/10/5 configurables, eliminar días gratis para nuevas aceptaciones, publicaciones previas conservan términos sin cobro, carreras aceptadas no se recalculan. Retiros y crédito no están habilitados en producción todavía.
